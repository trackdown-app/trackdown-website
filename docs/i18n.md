# Internationalisation

The site speaks Dutch and English through [Paraglide JS](https://inlang.com/m/gerre34r/library-inlang-paraglideJs). Trackdown starts with the Dutch rail network, so Dutch is the base locale; English makes it playable for visitors and expats.

## Locale routing

The locale lives in the URL so every language has its own indexable address:

- Dutch at `/`, `/play`, …
- English under `/en`: `/en`, `/en/play`, …

`paraglide.config.ts` sets the `url` strategy with the base locale as fallback; Paraglide's default URL patterns put the base locale at the root and every other locale behind its own prefix. `trailingSlash: "never"` keeps the English home at `/en`; a browser asking for `/en/` is redirected to the address without the slash.

Routes are declared once, without a locale. `src/router.tsx` gives the router a `rewrite`: `deLocalizeUrl` strips the prefix from an incoming URL before matching, and `localizeUrl` adds the current locale's prefix to every link the router renders. On the server, `paraglideMiddleware` in `src/server.ts` resolves the locale from the request URL and scopes it to that request, so `getLocale()` and the message functions answer in the right language during the server render. The root route sets `<html lang>` from `getLocale()`.

Paths are the same in both languages: an English page has the Dutch page's path behind `/en`. That keeps one route tree and one `<Link to>` per page.

## Language switch

`LanguageSwitch` (`src/components/language/language-switch.tsx`) is the NL / EN switch. It links to the current page in each language, query string kept (`localeSwitchHref` in `src/lib/locale-switch.ts`), with `hreflang` and `lang` on each link and `aria-current` on the current language. Each link shows its code (`NL`, `EN`) and adds the language's name (`language.nl`, `language.en`) in a visually hidden span, so its accessible name starts with what it shows. Each link is 44px high, and 44px wide on a touch screen. It sits at the end of the header on every page ([site-shell.md](site-shell.md#header)).

- The links are plain `<a>`, not router links: the other language loads as a new document, so its text renders on the server in that language. There is no translation in the browser.
- The hash never reaches the server, so the switch adds it to the link when it is followed, by a click or a middle click into a new tab, when JavaScript runs. Without JavaScript the other language opens at the top of the page.

To link to a fixed page in a given language elsewhere, use `localizeHref(path, { locale })` from `@/paraglide/runtime`.

## Messages

- `messages/nl.json` and `messages/en.json` hold every visible string as nested JSON; Paraglide compiles each leaf to a function under its dotted id, used as `m["game.title"]()`.
- Read each message straight from `m` with a string literal. A computed key (`` m[`language.${locale}`] ``), or `m` passed on as a value, keeps every message in the browser's JavaScript, because the bundler can no longer see which are used. ESLint's `no-restricted-syntax` rule in `eslint.config.mts` refuses both.
- `src/lib/messages-parity.test.ts` fails when the two files do not declare the same message ids, because Paraglide would otherwise fall back to Dutch without a word.
- Locales and the message file pattern are in `project.inlang/settings.json`. inlang writes its own `.gitignore`, `README.md` and cache into that folder; only `settings.json` is committed.

## Compiling

The compiled messages and runtime live in `src/paraglide/`, which is generated and not committed.

- `bun run dev` and `bun run build` compile through `paraglideVitePlugin` in `vite.config.ts`.
- `bun run paraglide:compile` (`scripts/compile-paraglide.ts`) compiles outside Vite with the same options. It runs on `postinstall` and as the first step of `typecheck`, `lint` and `test`, so a fresh checkout has the output before anything reads it. It skips the compile when a stamp in `node_modules/.cache/` still matches the inputs (settings, message files, `paraglide.config.ts`, `bun.lock`) and the output; `--force` always compiles.

## Tests

`src/test/setup.ts` puts the base locale back after every test. A test switches the language with `overwriteGetLocale(() => "en")`. `renderAt` (`src/test/render-at.tsx`) renders a component inside a memory router, for components that read the location, such as the language switch. It takes the path without a locale, opens it in the current locale and gives the router the site's locale rewrite, so a router `<Link>` points under `/en` in an English test as on the site.
