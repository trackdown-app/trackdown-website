# Internationalisation

The site speaks Dutch, English, German and French through [Paraglide JS](https://inlang.com/m/gerre34r/library-inlang-paraglideJs). Trackdown starts with the Dutch rail network, so Dutch is the base locale; English, German and French make it playable for visitors, expats and the neighbours.

## Locale routing

The locale lives in the URL so every language has its own indexable address:

- Dutch at `/`, `/play`, …
- English under `/en`: `/en`, `/en/play`, …
- German under `/de`: `/de`, `/de/play`, …
- French under `/fr`: `/fr`, `/fr/play`, …

`paraglide.config.ts` sets the `url` strategy with the base locale as fallback and lists its `urlPatterns`: English, German and French behind their prefix, and the base locale at the root, last, because its pattern matches every path. Paraglide's default patterns say the same, but also strip a leading `/nl` as the Dutch prefix, which would take the Dutch network's pages at `/nl` ([network-picker.md](network-picker.md#routes)); with the patterns listed, `/nl` is a path like any other. `trailingSlash: "never"` keeps each home at `/en`, `/de`, `/fr`; a browser asking for `/en/` is redirected to the address without the slash.

A locale prefix is taken from every network's page: a network whose id were `de` or `fr` would lose `/de` to the German home. `src/lib/data/networks.test.ts` fails when a network id is a locale prefix, so the German or a French network takes another id ([network-picker.md](network-picker.md#adding-a-network)).

Routes are declared once, without a locale. `src/router.tsx` gives the router a `rewrite`: `deLocalizeUrl` strips the prefix from an incoming URL before matching, and `localizeUrl` adds the current locale's prefix to every link the router renders. On the server, `paraglideMiddleware` in `src/server.ts` resolves the locale from the request URL and scopes it to that request, so `getLocale()` and the message functions answer in the right language during the server render. The root route sets `<html lang>` from `getLocale()`.

Paths are the same in every language: an English, German or French page has the Dutch page's path behind `/en`, `/de` or `/fr`. That keeps one route tree and one `<Link to>` per page.

## Language switch

`LanguageSwitch` (`src/components/language/language-switch.tsx`) is the NL / EN / DE / FR switch. It links to the current page in each language, query string kept (`localeSwitchHref` in `src/lib/locale-switch.ts`), with `hreflang` and `lang` on each link and `aria-current` on the current language. Each link shows its code (`NL`, `EN`, `DE`, `FR`) and adds the language's name (`language.nl`, `language.en`, `language.de`, `language.fr`) in a visually hidden span, so its accessible name starts with what it shows. Each link is 44px high, and 44px wide on a touch screen. It sits at the end of the header on every page ([site-shell.md](site-shell.md#header)).

- The links are plain `<a>`, not router links: the other language loads as a new document, so its text renders on the server in that language. There is no translation in the browser.
- The hash never reaches the server, so the switch adds it to the link when it is followed, by a click or a middle click into a new tab, when JavaScript runs. Without JavaScript the other language opens at the top of the page.

To link to a fixed page in a given language elsewhere, use `localizeHref(path, { locale })` from `@/paraglide/runtime`.

## Messages

- `messages/nl.json`, `messages/en.json`, `messages/de.json` and `messages/fr.json` hold every visible string as nested JSON; Paraglide compiles each leaf to a function under its dotted id, used as `m["game.title"]()`.
- German speaks to the player as `du` and French as `tu`, as Dutch says `je`. German uses „…“ quotes; French writes « … » and puts a no-break space (` `) before `:`, `;`, `?`, `!` and `%`.
- Read each message straight from `m` with a string literal. A computed key (`` m[`language.${locale}`] ``), or `m` passed on as a value, keeps every message in the browser's JavaScript, because the bundler can no longer see which are used. ESLint's `no-restricted-syntax` rule in `eslint.config.mts` refuses both.
- `src/lib/messages-parity.test.ts` fails when a locale's file does not declare the same message ids as the Dutch one, because Paraglide would otherwise fall back to Dutch without a word.
- A few things are worded per locale in code rather than messages, each a `Record<Locale, …>` so a new locale fails the typecheck until it has them: the language switch's names, `og:locale` (`src/lib/seo.ts`), the puzzle's date (`src/lib/game/puzzle-date-label.ts`) and the provinces' names (`src/lib/game/province-names.ts`).

### Adding a locale

1. Its code in `project.inlang/settings.json`'s `locales`, and its pattern in `paraglide.config.ts`'s `urlPatterns`, before the base locale's.
2. `messages/{locale}.json` with every message, and `language.{locale}` in every other file.
3. Its entries in the `Record<Locale, …>` maps above; the typecheck lists them.
4. `bun run openapi`: the `stations` operation's `locale` lists the site's locales ([api.md](api.md#stations)).
5. `e2e/pages.ts`'s `pageLocales`, so axe checks its pages.
- Locales and the message file pattern are in `project.inlang/settings.json`. inlang writes its own `.gitignore`, `README.md` and cache into that folder; only `settings.json` is committed.

## Compiling

The compiled messages and runtime live in `src/paraglide/`, which is generated and not committed.

- `bun run dev` and `bun run build` compile through `paraglideVitePlugin` in `vite.config.ts`.
- `bun run paraglide:compile` (`scripts/compile-paraglide.ts`) compiles outside Vite with the same options. It runs on `postinstall` and as the first step of `typecheck`, `lint` and `test`, so a fresh checkout has the output before anything reads it. It skips the compile when a stamp in `node_modules/.cache/` still matches the inputs (settings, message files, `paraglide.config.ts`, `bun.lock`) and the output; `--force` always compiles.

## Tests

`src/test/setup.ts` puts the base locale back after every test. A test switches the language with `overwriteGetLocale(() => "en")`. `renderAt` (`src/test/render-at.tsx`) renders a component inside a memory router, for components that read the location, such as the language switch. It takes the path without a locale, opens it in the current locale and gives the router the site's locale rewrite, so a router `<Link>` points under `/en` in an English test as on the site.
